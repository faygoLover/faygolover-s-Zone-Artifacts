# fl_zone_arts — faygolover's Zone Artifacts

Minecraft Forge 1.20.1 (47.4.10). Мод аномалий и артефактов для сервера "Департамент".

**Этап 1 (этот код): только Электра**, но написана так, чтобы движок объёмных зон
(`faygolover.zoneartifacts.anomaly`) переиспользовался для Жарки/Инея/Лифта/Воронки в будущем
почти без нового Java-кода — только новые файлы датапака.

## Открыть в IntelliJ

1. Открыть папку проекта как Gradle-проект (File → Open → выбрать `build.gradle`).
2. Дождаться Gradle sync — при первой синхронизации ForgeGradle скачает Minecraft, маппинги
   и создаст run-конфигурации `runClient` / `runServer` / `runData`. Нужен реальный интернет
   (в этой песочнице доступа к maven.minecraftforge.net не было, поэтому сборка здесь
   не проверялась «живьём» — см. раздел «Что стоит перепроверить» ниже).
3. Запустить конфигурацию `runClient` (появится в Run Configurations после sync, либо
   `./gradlew runClient` из терминала).

## Что реализовано

- **Датапак-загрузчик** (`AnomalyTypeManager`) читает `data/fl_zone_arts/anomaly_types/*.json`,
  валидирует поля, при ошибке пишет в лог файл + конкретное поле и пропускает только этот файл
  (остальной датапак продолжает грузиться).
- **Движок объёмной зоны** (`AnomalyEngine` + `AnomalyType`/`AnomalyShape`/... records):
  форма `cube` по уровню, детект игрок/моб/брошенный предмет, урон через кастомный
  data-driven `damage_type`, кулдаун, фоновые и одноразовые частицы/звук — всё из JSON.
- **Персистентность** (`AnomalySavedData`) — аномалии переживают перезапуск сервера.
- **Предмет-установщик** (`AnomalyPlacerItem`, один экземпляр — `electra_placer`):
  - ПКМ по блоку без аномалии → ставит уровень 1;
  - ПКМ по блоку с уже стоящей аномалией этого типа → цикл уровня 1→2→3→1;
  - Shift+ПКМ по аномалии → убирает.
- **Подсветка в руке** (`AnomalyHighlightRenderer`) — полупрозрачный объём с рёбрами
  в точке прицеливания, пока в руке предмет-установщик.
- Датапак самой Электры: `data/fl_zone_arts/anomaly_types/electra.json` +
  `data/fl_zone_arts/damage_type/anomaly_shock.json`.

## Как проверить в игре

```
/give @p fl_zone_arts:electra_placer
```

Предмет также есть в творческом инвентаре (вкладка "Zone Artifacts: Anomalies").
ПКМ по блоку — аномалия появится, будет потрескивать частицами `electric_spark` и гудеть;
зайдите в объём игроком/мобом/бросьте снежок — сработает урон (кроме снежка) + кулдаун 1 сек.

## Известные упрощения этого этапа

- **Подсветка всегда показывает уровень 1** для превью — клиент пока не знает реальный
  уровень уже стоящей аномалии (нет пакета синхронизации с сервера). Легко добавить позже.
- Триггеры `passive_field` и `phased` из дизайн-документа распознаются загрузчиком, но
  `AnomalyEngine` пока не реализует их поведение — это будущие Жарка/Иней/Карусель и т.п.
- Иконка предмета (`electra_placer.png`) — черновой плейсхолдер (диск + молния), замените
  на нормальный арт когда будет.
- Шкалы (радиация/пси) и артефакты — не в этом этапе, как и договаривались.

## На что обратить внимание при первой сборке

Всё, кроме одного файла, использует давно устоявшиеся, широко задокументированные API
Forge 1.20.1 (регистрация предметов, SavedData, data-driven damage types, JSON reload listener,
RenderLevelStageEvent). Собрать и проверить всё это «вживую» в песочнице не вышло — нет доступа
к Maven Forge/Mojang оттуда, — поэтому сборка не была протестирована локально.

Самый нестандартный кусок — **`client/ModRenderTypes.java`** (кастомный `RenderType` для
залитого полупрозрачного объёма). Если Gradle sync что-то подсветит именно там — это ожидаемо,
остальной код собирать проблем не должен. Если что-то не собирается — пришлите текст ошибки,
поправим.
